# Pコン跡分類 解法説明

SDNET2018 の壁画像（256×256 タイル）を対象に、Pコン跡があるかどうかを 2 値分類する。評価は陽性クラスの F1。

この解法では、タイルを元の写真（18 列 × 14 行）に並べ直し、周りのタイルを文脈として使う。そのうえで中央のタイルだけを見るモデルとタイル単体のモデルを組み合わせる。

数値の出典は `experiments.md` と `submissions/README.md`。2 章のデータ分析の数値だけは、Step 0 の出力 `outputs/eda/eda_summary.json` と `CLAUDE.md` 2 章から取った。

## 2. データ分析

### 2.1 タイル配置（18 列 × 14 行、行優先）の特定

1 枚の元写真は 252 枚のタイル（番号 1〜252）に切り出されている。並び順は次の 2 つの方法で確かめた。

**(1) ラベルから見た隣接関係**
- train の陽性タイルのペアについて、タイル番号の差を数えた。+1 が 63 組、+18 が 58 組、+17 と +19 が 20 組ずつだった。
- 1 つのPコン跡は 2〜4 枚のタイルにまたがって写る。そのため、行の幅が 18 なら「右隣 = +1、下 = +18、斜め = +17 / +19」になる。
- 行の幅を変えて「上下左右に陽性がある陽性タイルの割合」を計算した。幅 18 だけが 0.840 と高く、幅 14〜22 のほかの値は 0.59〜0.64 にとどまった。

**(2) 画像の境界のつながり**
- train の全写真について、仮説ごとに「隣り合うタイルの境界画素の平均差」を計算した（18,877 組）。

| 仮説 | 横の境界 | 縦の境界 | 全体 |
|---|---|---|---|
| 参考: タイル内部の隣接画素 | 3.21 | 3.15 | — |
| **A 行優先 18 列 × 14 行** | **3.30** | **3.23** | **3.26** |
| B 行優先 17 列 | 3.74 | 8.88 | 6.30 |
| C 行優先 19 列 | 3.74 | 8.82 | 6.26 |
| D 18 列・番号を 1 ずらし | 3.81 | 3.23 | 3.52 |
| E 列優先 14 行 × 18 列 | 10.86 | 9.52 | 10.20 |
| F ランダムな並び | 12.57 | 12.54 | 12.55 |

- 仮説 A の境界差は、タイル内部の隣接画素の差とほぼ同じだった。つまり、つなぎ目がほとんど見えない。
- 各タイルの右端に最もよくつながるタイルを全候補から探した。番号 +1 が 99.4%（9,465 / 9,519）、下端では +18 が 99.5%（9,310 / 9,359）だった。
- 行の折り返し（18 列目 → 次の行の 1 列目）の境界差は 11.58 で、つながっていない。
- test でも同じ結果になった（仮説 A の全体平均 3.26）。復元した写真は目視でも確認した（`outputs/eda/photo_*_rowmajor18*.jpg`）。

## 4. 検証方法

- **fold**: 写真 ID をグループとした 5 fold（`outputs/folds.csv`、seed 42）。すべての実験で同じものを使った。
  - sklearn の StratifiedGroupKFold では、fold ごとの陽性数が 32〜47 とばらついた。
  - そこで、写真の割り当てを乱数で探索し、陽性数が均等になる分け方を採用した（`src/data.py:250` `make_folds`）。各 fold の陽性は 38〜39。
- **評価指標**: 全 fold の OOF を結合して計算した F1（pooled OOF F1）。
  - しきい値は OOF 上で 0.01 刻みに探索する。前後 ±0.05 の F1 で、山がなだらかかどうかも確認する。
  - あわせて fold 別 F1、AP、予測陽性率、隣接率（予測陽性のうち上下左右にも予測陽性がある割合。train 正解では 0.840）を記録した。
- **(a) と (b)**: (a) は fold ごとに valid F1 が最良の epoch、(b) は最終 epoch（10 epoch 目）の重み。
  - (a) は valid を見て epoch を選ぶので、OOF F1 が楽観的に出る。
  - (b) は valid を使わずに決まり、test 推論と同じ条件になる。そのため Step 2 以降の判断はすべて (b) で行った。
  - exp006 の例では、確率平均の F1 が (a) 0.8842 / (b) 0.8802 で差は小さかった。
- **ノイズの扱い**: 陽性が 194 件しかないので、OOF F1 の差 0.01〜0.02 はノイズとみなした。
- **採用条件は実行前に決めた**。たとえば exp011・exp013・exp014 では、学習前に次の条件を決めてから判定した。
  1. exp009 より OOF F1 が 0.01 以上高い
  2. 5 fold 中 3 fold 以上で exp009 以上
  3. しきい値 ±0.05 の F1 がどちらも 0.8827 以上（exp009 の ±0.05 の小さい方 − 0.005。exp013 以降）
- **public スコアは使わない**: public は test 32 写真の一部だけで計算されるので、ぶれが大きい。形式の確認と、CV との大きな食い違いがないかの確認にだけ使い、public に合わせた調整はしなかった。

| exp001b | exp001 を 10 epoch に | 0.8407 | 基準 | 以降の比較基準（4.7 分） |

| exp004 | 周辺文脈 m=256（768→512） | 0.8114 | 不採用 | F1 低下 |

| exp005 | exp003 の global average pooling を、中央 4×4（中央タイル相当）の平均に置換 | 0.8571 | 採用 | exp003 0.816 → 0.857、AP 0.868 → 0.896、FN 43 → 23 |

| exp011 | exp009 + exp010 の等重み平均 | 0.8901 | 不採用 | exp009 比 +0.0012 < +0.01 |
| exp012 | exp005 の出力を 3×3 タイル同時予測に（AdaptiveAvgPool2d(3) → 1×1 conv、マスク付き BCE） | 0.8866 | 単体最良 | exp005 比 +0.030、AP 0.896 → 0.928 |
| exp013 | exp009 + exp012（1 seed）の等重み平均 | 0.8964 | 不採用 | exp009 比 +0.0075 < +0.01 |
| exp014 | exp013 の exp012 を 2 seed 平均に | 0.8906 | 不採用 | exp009 比 +0.0017 < +0.01 |

### exp013 → exp014: seed を足すと 0.896 → 0.891 に下がった

- exp013 は exp012 を 1 seed だけ使い、OOF F1 0.8964 だった。exp009 比 +0.0075 で、採用条件の +0.01 には届かなかった。fold は 4/5 で exp009 以上、±0.05 も基準内だった。
- 確かめるために exp012 を seed 1042 でもう 1 本学習した（exp012_s1）。単体の 9 crop 平均は 0.8842 で、1 本目は 0.8866。
- 2 seed 平均の exp012 系は OOF F1 0.8852、AP 0.927。これを使った exp014 は 0.8906 で、exp009 比 +0.0017 にとどまった。
- seed を増やして平均すると、本来は予測が安定して良くなる方向に働く。それでも F1 が下がったのは、exp013 の +0.0075 の多くが、1 本目の seed の当たりによるものだったからとみられる。
- 事前に決めた条件で判定したので、この「当たり」を採用せずに済んだ。fold の標準偏差は 0.052 → 0.038 に縮み、弱い fold 0・2 は上がったが、全体の差はノイズの範囲にある。

## 6. 効かなかった実験と原因

### 6.1 周辺文脈を入れると F1 が下がった（exp002 / 003 / 004）

- AP は上がった（exp001b 0.797 → exp003 0.868）が、F1 は 0.841 → 0.805〜0.816 に下がった。
- 文脈入力モデルの FP は 63〜86% が正解陽性の 8 近傍にあった（exp001b は 8〜11%）。周辺にPコン跡があることは捉えていたが、それが中央のタイルに入っているかを区別できていなかった。
- 予測陽性の隣接率も、exp003 (a) で 0.904 と正解の 0.840 を上回り、陽性の周りに予測が広がっていた。
- 原因は global average pooling で、中央の位置情報が失われる。中央 4×4 だけを平均する exp005 に変えると、F1 0.816 → 0.857、FN 43 → 23 と改善した。
- ただし、exp005 でも FP の 50% はまだ 8 近傍にある。

### 6.2 2 段目モデル（exp007）

- 1 段目（exp001b + exp005）の OOF 確率を写真の盤面に並べ、近傍の確率から特徴量を作って LR / HistGradientBoosting で分類し直した。
- 結果は LR 位置あり 0.8861 が最良で、単純平均の exp008（0.8877）を超えなかった。
- 原因: 近傍の FP は、exp001b（7%）と exp005（50%）を平均した時点で 16% まで減っていた。2 段目で減らせる余地が小さかった。重要度も自身の確率が支配的で、位置特徴の効果は ±0.006 とノイズの範囲だった。

### 6.3 exp010（m=128・512×512 に中央プーリング）

- exp010 の OOF F1 は 0.8273 で、exp005（m=256・384 に縮小）の 0.8571 より 0.030 低い。AP も 0.875 対 0.896。
- FP のうち 8 近傍にあるものは 49%（47 件中 23 件）で、exp005 の 50% と変わらなかった。中央プーリングにしても、近傍への位置ずれは減らなかった。
- 中央プーリングを入れる前の exp002（m=128）も、文脈モデルの中で最も F1 が低かった（0.8053）。

### 6.4 TTA

- 単体では exp001b 0.8407 → 0.8443、exp005 0.8571 → 0.8641 と上がった。
- アンサンブル（exp008）では 0.8877 → 0.8872 となり、効果がなかった。モデル平均で十分に滑らかになっていて、TTA で足せる分が残っていないとみられる。

## 9. 再現手順（final_candidate.csv = exp009）

実際に使ったコマンド。`python` は README.md の手順で作った環境（Python 3.12、PyTorch 2.10.0+cu128）の Python。

```bash
# 0. config.yaml の sdnet_root に SDNET2018 のパスを書いておく
# 1. 画像キャッシュと fold の作成（outputs/cache/, outputs/folds.csv）
python -m src.data
python -m src.data --make-folds --force
python -m src.eda                      # 任意: 配置の検証と EDA

# 2. 1 段目モデルの学習（5 fold × 10 epoch）と test 推論（(b) 最終 epoch）
for e in exp001b exp001b_s1 exp001b_s2 exp001b_s3 exp005 exp005_s1 exp005_s2 exp005_s3; do
  python -m src.train --exp configs/$e.yaml
  python -m src.infer --exp outputs/$e --which last
done

# 3. seed 平均 → 等重み平均（outputs/exp009/、しきい値は OOF 上で決まる: 0.72）
python -m src.final_ensemble --name exp009 \
  --group exp001b exp001b_s1 exp001b_s2 exp001b_s3 \
  --group exp005 exp005_s1 exp005_s2 exp005_s3

# 4. 提出ファイルの作成と形式チェック（CLAUDE.md 8 章）
python -m src.make_submission --exp outputs/exp009 --which last --pred test_pred_last.csv \
  --out submissions/final_candidate.csv --note "..."
```
